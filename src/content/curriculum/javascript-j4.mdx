## 2. KONSEP INTI: Arsitektur Test Runner & Matchers Vitest

Berdasarkan dokumentasi resmi [Vitest Documentation](https://vitest.dev/) dan panduan pengujian [MDN Web Docs: Testing](https://developer.mozilla.org/en-US/docs/Learn/Tools_and_testing), arsitektur test runner profesional bertumpu pada 4 pilar:

1. **Struktur Pengorganisasian Hierarkis:**
   - `describe(judul, fn)`: Membungkus kelompok modul atau domain bisnis (*test suite*).
   - `it(skenario, fn)` atau `test(...)`: Mendefinisikan satu skenario perilaku spesifik (*test case*).
2. **Assertion & Matchers:**
   - `expect(actual).toBe(expected)`: Memeriksa kesetaraan identitas referensi menggunakan `Object.is`. Cocok untuk tipe data primitif (`number`, `string`, `boolean`).
   - `expect(actual).toEqual(expected)`: Memeriksa kesetaraan struktural mendalam (*deep equality*). Wajib digunakan untuk objek dan array!
   - `expect(actual).toContain(item)`: Memeriksa keberadaan elemen di dalam array atau substring pada teks.
3. **Pola Pengujian Red-Green-Refactor:**
   - **Red:** Tulis tes yang gagal karena fiturnya belum dibuat.
   - **Green:** Tulis kode seminimal mungkin hingga seluruh assertion berhasil lolos (hijau).
   - **Refactor:** Bersihkan dan optimalkan struktur kode tanpa mengubah hasil tes.
4. **Isolasi State & Anti State-Leak:**
   - Setiap tes wajib memiliki state independen. Pengujian yang baik tidak bergantung pada urutan eksekusi tes lain.

  title="Latihan J4.1: Membangun Assertion Matchers (toBe, toEqual, toContain)"
  initialCode={`const expect = (actual) => ({
  toBe: (expected) => {
    if (!Object.is(actual, expected)) {
      throw new Error("Expected " + expected + " but received " + actual);
    }
    return true;
  },
  toEqual: (expected) => {
    if (JSON.stringify(actual) !== JSON.stringify(expected)) {
      throw new Error("Structural mismatch: expected " + JSON.stringify(expected) + " but got " + JSON.stringify(actual));
    }
    return true;
  },
  toContain: (item) => {
    if (!Array.isArray(actual) || !actual.includes(item)) {
      throw new Error("Array does not contain " + item);
    }
    return true;
  }
});

// Verifikasi assertion matcher
console.log("Test toBe:", expect(100).toBe(100));
console.log("Test toEqual:", expect({ role: "admin" }).toEqual({ role: "admin" }));
console.log("Test toContain:", expect(["JS", "Python", "Rust"]).toContain("Python"));`}
  expectedOutput={`Test toBe: true\nTest toEqual: true\nTest toContain: true`}

  title="Latihan Mandiri J4.4: In-Memory Reactive Store dengan Subscription Pattern"
  initialCode={`const createStore = (initialState) => {
  let state = { ...initialState };
  const listeners = new Set();

  return {
    getState: () => ({ ...state }),
    setState: (updater) => {
      state = typeof updater === "function" ? updater(state) : { ...state, ...updater };
      listeners.forEach((listener) => listener(state));
    },
    subscribe: (listener) => {
      listeners.add(listener);
      return () => listeners.delete(listener);
    }
  };
};

const store = createStore({ counter: 0 });
const logHistory = [];

const unsubscribe = store.subscribe((s) => {
  logHistory.push("Nilai: " + s.counter);
});

store.setState((prev) => ({ counter: prev.counter + 1 }));
store.setState((prev) => ({ counter: prev.counter + 4 }));
unsubscribe();
store.setState({ counter: 99 }); // listener tidak dipanggil setelah unsubscribe

console.log("Riwayat State:", logHistory.join(", "));
console.log("State Akhir:", store.getState().counter);`}
  expectedOutput={`Riwayat State: Nilai: 1, Nilai: 5\nState Akhir: 99`}

## 6. KESALAHAN UMUM (COMMON MISCONCEPTIONS)

1. **Miskonsepsi `toBe` untuk Array/Objek:** Pemula sering menulis `expect([1, 2]).toBe([1, 2])` dan heran mengapa tes gagal (*red*). `toBe` memeriksa identitas pointer memori (`Object.is`). Dua array berbeda tidak akan pernah memiliki alamat heap yang sama. Gunakan `toEqual`.
2. **Miskonsepsi Lupa Menangani Async Assertion:** Menjalankan promise di dalam `it()` tanpa kata kunci `await` menyebabkan tes berstatus lulus semu (*false positive*) karena eksekusi tes selesai sebelum promise melempar rejection error.
3. **Miskonsepsi Berbagi Mutasi State Antar Tes (*Shared State Pollution*):** Menggunakan variabel global yang dimutasi oleh Tes A sehingga menyebabkan Tes B gagal secara acak saat urutan tes dibalik. Selalu buat instansiasi baru (*fresh instance*) untuk setiap unit tes.
4. **Miskonsepsi Testing Implementation Details:** Menguji nama variabel internal privat daripada menguji perilaku (*behavior/output*) publik. Jika Anda merefaktor kode internal tanpa mengubah fungsionalitas, unit test tidak boleh rusak.
