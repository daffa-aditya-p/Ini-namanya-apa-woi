## 2. KONSEP INTI: Arsitektur Konkurensi & Siklus Hidup Asinkron

Berdasarkan standar resmi [MDN Web Docs: Asynchronous JavaScript](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Asynchronous) dan tutorial praktis [W3Schools JavaScript Promises](https://www.w3schools.com/js/js_promise.asp), tiga fondasi penanganan asinkron modern yang wajib kamu kuasai:

1. **Prioritas Antrean Event Loop:**
   - **Call Stack:** Mengeksekusi instruksi sinkron baris per baris.
   - **Microtask Queue:** Antrean berprioritas tinggi. Seluruh antrean microtask harus kosong sebelum browser melakukan render layar atau mengambil task berikutnya.
   - **Macrotask Queue:** Antrean pekerjaan berprioritas normal (timer, event I/O).
2. **Orkestrasi Promise Combinators:**
   - `Promise.allSettled()`: Menunggu semua promise selesai (baik `fulfilled` maupun `rejected`). Pola paling tangguh untuk dasbor analitik multi-sumber karena tidak langsung patah jika salah satu layanan mati.
   - `Promise.all()`: Pola *fail-fast*; langsung menolak jika satu saja promise mengalami error.
   - `Promise.race()`: Mengambil hasil pertama yang selesai (cocok untuk pembatas waktu/deadline).
3. **Penyelamat Timeout: AbortController:**
   - Mekanisme standar web modern untuk membatalkan sinyal komputasi atau request `fetch` yang berjalan terlalu lambat, mencegah pemborosan memori dan bandwidth.

## 6. KESALAHAN UMUM (COMMON MISCONCEPTIONS)

1. **`try/catch` Sinkron Gagal Menangkap Error Callback:** Menulis `try { setTimeout(() => { throw new Error(); }, 100); } catch (e) { ... }` tidak akan pernah menangkap exception karena blok try/catch sudah selesai dieksekusi dan keluar dari call stack jauh sebelum callback pewaktu dipicu. Solusinya: bungkus operasi dalam Promise atau gunakan fungsi `async`.
2. **`Array.prototype.forEach` dengan Fungsi `async`:** Memanggil `items.forEach(async (item) => { await proses(item); })` tidak akan menunggu proses asinkron selesai. `forEach` tidak mempedulikan nilai kembalian Promise. Solusinya: gunakan perulangan berurutan `for (const item of items) { await proses(item); }` atau jalankan secara konkruen dengan `await Promise.all(items.map(proses))`.
3. **Patah Total Akibat `Promise.all` (*Fail-Fast*):** Memakai `Promise.all` untuk mengambil data dari sepuluh API independen. Jika salah satu API gagal (misal 500 internal server error), seluruh hasil akan ditolak dan aplikasi tidak menampilkan apa pun. Gunakan `Promise.allSettled` untuk sistem toleran galat di mana hasil yang sukses tetap dapat disajikan.
4. **Kebocoran Memori AbortSignal (*Listener Leaks*):** Mendaftarkan event listener `signal.addEventListener('abort', fn)` tanpa menghapusnya saat Promise berhasil diselesaikan lebih awal. Hal ini menyebabkan controller tetap menahan referensi ke closure fungsi di heap memori.

**Deskripsi Tugas Mandiri:**
Rancang modul aggregator asinkron yang memadukan data dari 3 sumber independen:

3. Menyimpan data yang berhasil ke simulator cache in-memory dengan waktu kedaluwarsa 60 detik.
