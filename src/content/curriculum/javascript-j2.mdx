## 2. KONSEP INTI: Transformasi Data FP & Model Memori

Pemrograman fungsional & modular modern di JavaScript bersandar pada pilar utama:
1. **Purity & Immutability:** Jangan mengubah array/objek asli; hasilkan struktur data baru (via `structuredClone` atau immutable methods seperti `toSorted`).
2. **First-Class Functions:** Fungsi dapat dikirimkan sebagai argumen (`map`, `filter`, `reduce`) dan dikembalikan dari fungsi lain.
3. **Closure & Heap Persistence:** Ketika fungsi luar selesai dieksekusi, variabel di dalam lingkup leksikalnya tidak langsung dihancurkan oleh Garbage Collector jika masih direferensikan oleh fungsi dalam (*inner function*).
4. **ES Modules (ESM) & Batas Modular:** Standar resmi ECMAScript (`import` / `export`) yang menggantikan CommonJS, dievaluasi secara statis pada fase parsing untuk mengisolasi scope modul dan mendukung tree-shaking efisien.

## 6. KESALAHAN UMUM (COMMON MISCONCEPTIONS)

1. **Miskonsepsi Shallow Copy:** Menggunakan spread syntax `const copy = { ...asli }` mengira menyalin seluruh objek bersarang (*nested objects*). Kenyataannya, properti objek bersarang tetap berupa referensi pointer yang sama! Perubahan pada `copy.alamat.kota` akan memutasi `asli.alamat.kota`. Gunakan `structuredClone(asli)`.
2. **Miskonsepsi Callback Loop:** Menggunakan `forEach` saat membutuhkan array hasil transformasi. `forEach` tidak mengembalikan array (return `undefined`). Gunakan `map()`.
3. **Miskonsepsi Konteks `this`:** Memanggil method objek yang menggunakan arrow function dan mengharapkan `this` merujuk ke instance objek. Arrow function tidak memiliki binding `this` sendiri melainkan mewarisi leksikal dari scope luarnya.
4. **Miskonsepsi Evaluasi Dinamis ES Modules:** Mengira pernyataan `import ... from ...` dapat ditaruh di dalam blok percabangan `if (...)`. Deklarasi `import` bersifat statis dan selalu di-hoist saat fase parsing sebelum kode berjalan. Untuk pemuatan modul dinamis kondisional saat runtime, gunakan fungsi `import("modul.js")` yang mengembalikan Promise.

## 8. SELAMI LEBIH DALAM (DIVE DEEPER)

- **Spesifikasi Formal TC39:** Telusuri spesifikasi [ECMA-262 §23.1.3](https://tc99.es/ecma262/) mengenai *Ordinary Object Internal Methods* dan *Array Exotic Objects*.
- **V8 Engine Garbage Collection:** Bagaimana V8 Engine membedakan alokasi generasi muda (*Nursery/Scavenger*) dan generasi tua (*Mark-Sweep-Compact*) pada variabel closure yang tertahan lama di memori heap.
