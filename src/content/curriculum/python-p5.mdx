## 2. KONSEP INTI: Fondasi & 3 Pilar Utama OOP

Berdasarkan arsitektur resmi Python Data Model, mari kita bedah fondasi utama dan 3 pilar yang wajib dikuasai setiap developer handal:

### Fondasi Awal: Class, Object, dan Parameter `self`
1. **Class (Cetak Biru / Blueprint):** Sketsa rancangan konseptual. Misal cetak biru `Kucing` mendefinisikan bahwa setiap kucing punya nama, warna bulu, dan bisa mengeong.
2. **Object / Instance (Wujud Nyata di Dunia):** Realisasi konkret dari cetak biru di memori komputer. Misal `oyen = Kucing("Oyen", "Oranye")` dan `blacky = Kucing("Blacky", "Hitam")`.
3. **Konstruktor `__init__`:** Pabrik perakit otomatis yang dijalankan saat objek baru pertama kali diciptakan untuk mengisi data awalnya.
4. **Parameter `self`:** Alamat KTP atau tanda pengenal objek itu sendiri di memori. Saat kamu menulis `oyen.makan()`, Python di belakang layar menjalankannya sebagai `Kucing.makan(oyen)`. Parameter `self` memastikan si Oyen yang kenyang, bukan si Blacky!

---

### Pilar 1: Enkapsulasi (Bungkus & Amankan Data)
**Kenapa data tidak boleh diubah sembarangan dari luar?**
Bayangkan jika siapa saja bisa langsung menulis `akun.saldo = -99999999` atau `akun.saldo = "gratis"`. Aplikasi perbankanmu langsung bangkrut dan rusak total!

Enkapsulasi membungkus data internal dan menyediakan "pintu gerbang resmi" yang aman:
- **Atribut Publik (`self.nama`):** Data umum yang aman dibaca dan diubah bebas.
- **Konvensi Protected (`self._saldo`):** Awalan **satu garis bawah** `_`. Ini kode etik programmer Python: *"Tolong ya, variabel ini urusan internal class, jangan diobrak-abrik langsung dari luar!"*
- **Private / Name Mangling (`self.__pin`):** Awalan **dua garis bawah** `__`. Python otomatis menyamarkan namanya di memori menjadi `_NamaClass__pin` sehingga terhindar dari konflik tabrakan nama dan tidak bisa diakses sembarangan.
- **Modern Getter & Setter (`@property`):** Cara paling elegan di Python. Kita membaca data seperti atribut biasa (`print(akun.saldo)`), tapi ada fungsi "satpam" di belakangnya (`@saldo.setter`) yang memvalidasi bahwa uang yang disetor tidak boleh bernilai negatif!

```python
# Analogi Satpam ATM:
class AkunBank:
    def __init__(self, saldo_awal):
        self._saldo = saldo_awal  # Protected: jangan diakses langsung!

    @property
    def saldo(self):
        return self._saldo  # Gerbang baca resmi (Getter)

    @saldo.setter
    def saldo(self, nominal):
        if nominal < 0:
            raise ValueError("Saldo tidak boleh negatif!")  # Satpam validasi!
        self._saldo = nominal
```

### Pilar 2: Pewarisan / Inheritance (Turunkan Sifat Tanpa Duplikasi)
Kenapa harus menulis ulang kode yang sama berkali-kali jika kita bisa mewarisinya?
Pewarisan memungkinkan class anak (*Child / Subclass*) mewarisi semua atribut dan method dari class induk (*Parent / Superclass*):
- Class induk: `Kendaraan` (punya `merk`, `kecepatan_maks`, dan method `gas()`).
- Class anak: `MobilBalap(Kendaraan)` (otomatis punya semua kelebihan `Kendaraan`, ditambah fitur baru seperti tangki `nos` dan method `aktifkan_nos()`).
- **Fungsi `super().__init__()`:** Jembatan resmi untuk meminta class induk merakit bagian dasarnya terlebih dahulu sebelum class anak memasang komponen tambahannya.

```python
# Analogi Cetak Biru Kendaraan -> Mobil Balap:
class Kendaraan:
    def __init__(self, merk, kecepatan_maks):
        self.merk = merk
        self.kecepatan_maks = kecepatan_maks

class MobilBalap(Kendaraan):
    def __init__(self, merk, kecepatan_maks, nos):
        # Minta class induk rakit komponen dasarnya:
        super().__init__(merk, kecepatan_maks)
        self.nos = nos  # Pasang komponen khusus balap
```

### Pilar 3: Polimorfisme (Satu Perintah, Beragam Bentuk)
Kata *Polymorphism* berasal dari bahasa Yunani: **Poly** (banyak) + **Morph** (bentuk).
Intinya sangat sederhana: **Satu nama method yang sama, perilakunya otomatis berbeda sesuai objek yang menjalankannya.**

Contohnya:
- Kita punya daftar karakter game: `[Ksatria(), Penyihir(), RobotPemanah()]`.
- Kita tidak perlu mengecek satu per satu dengan puluhan baris `if-else`. Cukup jalankan satu perulangan: `for k in party: k.serang()`.
- Objek masing-masing yang tahu cara terbaik mengeksekusinya! Ini disebut **Method Overriding** (anak menimpa cara kerja bawaan induk).
- **Duck Typing Khas Python:** Filosofi terkenal Python berbunyi: *"If it walks like a duck and quacks like a duck, it's a duck."* (Jika ia berjalan seperti bebek dan bersuara seperti bebek, maka anggap saja itu bebek). Python tidak peduli silsilah keturunan class-mu apa; selama objek tersebut punya method `serang()`, Python akan langsung menjalankannya dengan gembira tanpa banyak drama!

```python
# Analogi Satu Perintah Tombol [Serang] atau [Bersuara]:
for karakter in [Ksatria(), Penyihir(), RobotPemanah()]:
    print(karakter.serang())
# Ksatria      -> "Menebas pedang! (-50 HP)"
# Penyihir     -> "Melempar bola api! (-80 HP)"
# RobotPemanah -> "Menembak laser otomatis! (-65 HP)"
```

## 6. KESALAHAN UMUM (COMMON MISCONCEPTIONS / JEBAKAN UMUM)

1. **Lupa Menulis Parameter `self` di Method:**
   Sering terjadi pemula menulis `def sapa():` di dalam class. Saat dijalankan, muncul error menyebalkan: `TypeError: sapa() takes 0 positional arguments but 1 was given`. Ingat: Python secara otomatis selalu menyisipkan objek instance sebagai argumen pertama, sehingga method wajib menerima parameter `self`!
2. **Tertukar antara Atribut Class vs Atribut Instance:**
   Jika kamu mendeklarasikan variabel langsung di bawah `class Karakter:` (bukan di dalam `__init__`), variabel tersebut menjadi atribut milik bersama seluruh pemain. Mengubah nilainya di satu karakter bisa tanpa sengaja mengubah nilai seluruh karakter lain di server!
3. **Membuat Subclass tapi Lupa Memanggil `super().__init__()`:**
   Jika class anak membuat method `__init__` baru tanpa memanggil `super().__init__()`, konstruktor class induk TIDAK AKAN berjalan. Akibatnya, semua atribut warisan orang tua tidak pernah terinisialisasi.
4. **Mengira `__private` adalah Benteng Gaib yang Mutlak:**
   Di Python tidak ada keamanan mutlak. Awalan dua garis bawah `__pin` hanyalah mekanisme *Name Mangling* (disamarkan menjadi `_NamaClass__pin`). Slogan komunitas Python berbunyi: *"We are all consenting adults here"* — kita saling percaya dan menghormati konvensi, bukan mengunci kode seperti penjara.
5. **Memaksakan Rantai Pewarisan Terlalu Dalam (Over-engineering):**
   Jangan membuat hierarki silsilah yang terlalu rumit (`MakhlukHidup` -> `Hewan` -> `Mamalia` -> `Karnivora` -> `Kucing`). Sering kali prinsip Duck Typing dan komposisi sederhana jauh lebih bersih, fleksibel, dan mudah dibaca!
