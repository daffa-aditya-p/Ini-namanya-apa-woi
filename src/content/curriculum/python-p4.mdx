## 2. KONSEP INTI: Empat Pilar Rekayasa Python Lanjutan

Berdasarkan panduan resmi [Python 3.12 Documentation: Library Reference](https://docs.python.org/3/library/) dan [W3Schools Python Advanced](https://www.w3schools.com/python/), terdapat 4 fondasi rekayasa perangkat lunak Python:

1. **Unit Testing Bergaya Pytest:**
   - Gunakan pernyataan sederhana `assert aktual == ekspektasi` tanpa boilerplate kelas berat.
   - Menguji *boundary values*, percabangan kondisi, dan penanganan galat (*exception testing*).
2. **Dekorator & Higher-Order Functions (PEP 318):**
   - Fungsi adalah warga kelas satu (*first-class citizens*). Fungsi dapat menerima fungsi lain sebagai argumen dan mengembalikan fungsi pembungkus (*wrapper*).
   - Selalu pasang `@functools.wraps(fn)` pada wrapper agar metadata fungsi asli (`__name__`, `__doc__`) tidak tertimpa.
3. **Iterators & Generators (PEP 255):**
   - Kata kunci `yield` mengubah fungsi biasa menjadi generator.
   - Menghasilkan nilai secara bertahap saat diminta (*lazy evaluation*), sangat krusial saat membaca berkas gigabyte atau data streaming.
4. **Context Manager (PEP 343) & Konkurensi Asyncio (PEP 492):**
   - Protokol `__enter__` dan `__exit__` menjamin pembersihan resource (file, koneksi socket, lock database) dieksekusi secara deterministik.
   - `async def` mendefinisikan coroutine dan `await` menunda eksekusi tanpa memblokir thread utama, diorkestrasikan secara paralel via `asyncio.gather()`.

## 6. KESALAHAN UMUM (COMMON MISCONCEPTIONS)

1. **Miskonsepsi Eksekusi Instan Generator:** Mengira saat fungsi generator dipanggil `g = generator_fungsi()`, seluruh kode di dalam fungsi langsung dijalankan. Padahal tidak ada sebaris pun kode dalam fungsi yang berjalan hingga `next(g)` atau loop `for item in g` dieksekusi pertama kali.
2. **Miskonsepsi Lupa `@functools.wraps`:** Membuat dekorator tanpa `@functools.wraps` menyebabkan `fungsi.__name__` berubah menjadi `'wrapper'` dan string dokumentasi `__doc__` lenyap. Hal ini membingungkan modul testing dan debugger produksi.
3. **Miskonsepsi Mengembalikan `True` di `__exit__` Secara Ceroboh:** Jika method `__exit__` mengembalikan nilai `True`, seluruh exception yang terjadi di dalam blok `with` akan ditelan (*swallowed*) tanpa dilaporkan. Hanya kembalikan `True` jika exception tersebut memang secara sengaja telah ditangani tuntas.
4. **Miskonsepsi Memanggil Coroutine Tanpa `await`:** Menulis `hasil = fetch_data()` pada fungsi async tanpa `await`. Pemanggilan tanpa `await` hanya mengembalikan objek coroutine yang belum dijalankan (*unawaited coroutine warning*), bukan hasil data sesungguhnya.
